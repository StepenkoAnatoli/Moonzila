- Repository: Moonzila (Electron + TypeScript; identifiers still say MoonAliza). Your worktree is given in your brief; work ONLY there. Base: the commit your brief names, on `main-axuse`.
- Source of truth: `docs/specification/research-purge.md` (read all of it), `REQUIREMENTS-P5.md` in the run folder, and `docs/specification/research-review.md` for the retained store. - Node: `export PATH=/versions/node/v24.21.0/bin:$PATH`. `node_modules` is a symlink to the main checkout; never run `npm install`.
- Discipline (careful-coding): read the code you change and grep its callers first; red-first tests (write the test, see it fail for the right reason, then implement); every new test must fail with the guard it names removed - check this by temporarily removing the guard and say which you checked.
- Own only the files your brief lists. Need anything else? Stop and report; do not edit it.
- Commit only to your own branch (`build/p5-<unit>`, already checked out in your worktree), each time a step is green, with `git -c user.name=StepenkoAnatoli -c user.email=318295322+StepenkoAnatoli@users.noreply.github.com commit`. Do NOT push, merge, rebase, or create other branches; the lead integrates by cherry-pick. A commit touching `src/` must stage `docs/ARCHITECTURE.md` (the commit gate refuses otherwise). If a tool or command is refused by the permission system, do not work around it: report it.
- Never print, copy or ask for keys or tokens. None are needed.
- Filesystem tests must hold on Windows too: make links only as `symlink(target, alias, 'junction')` with both ends inside the test's own `mkdtemp` root (the project convention, AGENTS.md "Orchestrator facts"); assert by the product's refusal or `realpath`/`lstat`, never by a link's stored text; no file symlinks, no fixed host paths. A case Linux cannot build (a junction, Windows file id) is skipped the way existing guard tests skip it.
- Verification before you report: `npm run typecheck`, `npm run lint`, and `npx vitest run <your test files>` plus any existing test file covering code you changed. The Linux baseline has 74 known failures that need the Windows native helper (listed in `/home/user/task5-handoff/baseline-failing.json`, keyed "file > full name"); a failure outside that list is yours.
- If you touch anything under `src/`, update the matching row of `docs/ARCHITECTURE.md` (one short addition per change; the commit gate requires it).
- Report (max 500 words): working directory, branch and commit IDs; files changed; what each test proves and which guard-removal you checked; commands run with results, each marked verified / untested / expected; anything in the spec you found ambiguous or wrong; mistakes you made and fixed (or "nothing to report").
- Lessons from Phase 4 that are now rules: any Store or file handle a test opens is closed before cleanup (Windows cannot delete an open file, P4-34); a renderer test waits for the call itself or a state the reply produces, never an initial state (P4-35); an e2e expectation matches the panel's real text, including suffixes (P4-36); a test's own input must reach the guard it names, checked by running it alone with that guard removed (P4-37).
