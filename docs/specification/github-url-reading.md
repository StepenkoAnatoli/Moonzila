# Public GitHub URL reading

Moonzila 0.8 adds `read_github` to General chat and project conversations when the user supplies a supported public GitHub repository URL. Paste a URL such as `https://github.com/StepenkoAnatoli/MoonAliza` and ask for a repository review. The model can list folders and read text files without a local checkout or token. This does not attach a coding workspace; edits and commands still require a trusted local folder.

Supported: HTTPS github.com repository roots, tree and blob URLs, repository-relative file/directory paths, optional branch/tag/commit ref, and line pages (up to 200 lines). For refs containing slashes, use the root URL plus the separate ref argument. General websites, issues/PR pages, private authentication, cloning, remote writes and recursive whole-repository search are outside this tool. Repositories with over 1,000 entries in one directory may have incomplete listings; results explicitly mark limits.

The user supplies repository scope through saved user messages. Model output, repository content and tool results cannot add another repository. Main rederives the scope from the engine store, validates active run/epoch and session/project policy revisions, and rechecks after the read. Each run pins the selected ref to a commit and reports a commit-specific source URL. Follow-up runs resolve current refs again; no false claim of immutable cross-run history.

Main makes only unauthenticated GET requests to constructed `https://api.github.com/repos/...` endpoints, with no cookies, authorization, provider credentials or redirects. Requests have a 20-second deadline and 2 MiB response bound. Files must be ordinary UTF-8 text no larger than 256 KiB; output is bounded to 16,000 characters and 200 lines per call. Directory output is bounded to 200 entries and 35,000 characters. Protected/credential paths, exposed symlinks and submodules are excluded. GitHub's contents API can dereference an internal symlink itself; Moonzila never follows API-provided download URLs or external targets.

Public repository content is untrusted data, not tool permission. Results and read-only tool events persist in the conversation; no workspace operation/journal is fabricated for a network read. Stop and privacy changes discard late results. Source results obey the existing conversation context budget and may be excerpted; the model can request narrower line ranges. No inference/provider token is sent to GitHub. Local-only describes model inference; explicitly supplying a public GitHub URL permits the scoped public lookup disclosed by the composer.

Errors distinguish malformed URL, missing/unavailable-or-private repository/ref/path (404), rate limiting, denied requests, redirects, oversized responses, unsupported content and timeout. GitHub response bodies and raw transport errors are never surfaced as explanations. Local file tools separately reject URLs with guidance to use read_github; `.`, `./` and `.\` now denote the root for directory listing/search while traversal and secret exclusions stay enforced.

Verification includes a real unauthenticated Moonzila root/README read at `146ba4e52a48baf7e843c6d197ce42c8ebb1c9c7`, protocol/limit/cancellation tests, engine general-chat persistence/scope tests and a real Electron workflow whose network boundary supplies controlled GitHub responses. Exact-head CI and packaged evidence belong on the phase PR/release record.

Primary documentation checked October 1, 2026: [GitHub repository contents API](https://docs.github.com/en/rest/repos/contents) documents public access without authentication, base64 file content, ref selection, directory limits and link/submodule behavior. [Git trees API](https://docs.github.com/en/rest/git/trees) describes broader listing, which this bounded directory reader does not use.
