# Verified local artifacts

This implements the Stage D2 backend boundary. It is not yet a managed-model setup button, an enabled local model, or a released activation catalogue. Version 0.5 remains the installed desktop checkpoint.

## Trust and activation

`verifyCatalogue` accepts an Ed25519 envelope whose signed bytes have the domain prefix `MoonAliza activation set v1` followed by a NUL byte. Trusted public keys are application configuration; a document cannot supply its own trust root. The signature is checked before parsing artifact URLs. The parsed payload is strict and recursively frozen. Application compatibility, issued/expiry dates, monotonic sequence, unique identities and runtime/model/receipt references are checked separately.

Each runtime archive has a separately pinned file manifest. Activation checks the extracted files against that manifest, including byte sizes and SHA-256 hashes, and rejects additional files. Each model manifest has pinned configuration/layer blobs. A lab receipt must match the runtime archive, model manifest and evidence digests, the supported backend and suite, and the minimum quality/tool/cancellation requirements. Tests use generated test keys and synthetic receipts; none are shipped as a real qualification.

`ActivationStore` stages a complete set into an immutable directory, then replaces a single durable current-pointer file. It retains the prior directory and pointer identity. Interrupted partial staging is never current. A fully verified candidate left after directory rename can be revalidated and committed on retry. Reopening an activation rechecks the signed metadata, all cached artifacts, runtime files and the materialized model store. Model configuration quantization must agree with its lab receipt. Cancellation and candidate failure preserve the prior pointer. See [model materialization and selection](model-store-selection.md) for the exact-byte model store and derived-cache boundary.

The caller must supply `withRuntimeStopped`, an exclusive ownership lease that drains the managed runtime and keeps admission closed throughout activation. A point-in-time “is idle” check is insufficient. The [scheduler core](managed-scheduler.md) now supplies this callback, and an integration test verifies that activation has no download effects until a held inference lease is released. Production runtime-controller and main/IPC integration remain to be connected. No user-owned Ollama runtime is controlled by this module.

## Download and extraction

Downloads stream into a content-addressed cache and verify exact size and SHA-256 before publication. Existing cached files are rehashed. Selected-volume free space is checked with a 256 MiB reserve. Network requests carry no provider credentials or cookies and follow only explicit HTTPS redirect hosts. Public GET retries are bounded; long Retry-After responses return a rate-limit result rather than retrying early. Partial transfer resumption requires a strong ETag and matching Content-Range; a server that returns a full response causes a restart, never an append. Aborted or failed transfers retain partial bytes only when their identity can be validated on resumption.

ZIP extraction uses lazy entry iteration and streamed writes. It bounds entry count, filename metadata, declared expansion and actual bytes; checks CRC and SHA-256; rejects encryption, links, Windows device names, drive/UNC/alternate-stream paths, backslashes, dot/space aliases, duplicates and case collisions. It requires an absent destination and removes only its own partial directory on failure. Signed manifests remain the activation authority after extraction.

These app-owned directories reject existing link paths and hard-linked files, but JavaScript path rechecks are not a complete handle-relative defense against a hostile process with the same account's filesystem access. The cache currently retains artifacts conservatively. Reference-aware removal, storage relocation and full power-loss/filesystem qualification remain open.

Primary transport references: [HTTP range and validator semantics](https://www.rfc-editor.org/rfc/rfc9110.html), [yauzl lazy iteration, path and size checks](https://github.com/thejoshwolfe/yauzl). Collected source evidence is E-20/E-21 in the sibling research workspace. A direct 27 September observation of the official Ollama registry's Qwen3 0.6B manifest confirmed schema version 2, a configuration descriptor and layer descriptors with media type, size and SHA-256 digest. No model blob was downloaded by that observation.

## Real runtime evidence, 27 September 2026

The pinned Ollama 0.34.4 Windows amd64 ZIP was downloaded through the production downloader. GitHub's authenticated release API and its public release page agreed on **1,461,155,106 bytes** and SHA-256 **535193f38f3344e5b08f5d1c171c31ce11aa17f0124ff69ae26d8ec7fe06fa62**. The supplied GitHub token was used only for release metadata after anonymous API access returned 403. Archive downloads did not receive that credential. [Official pinned asset listing](https://github.com/ollama/ollama/releases/expanded_assets/v0.34.4)

The complete download hash passed. The actual archive contains 87 entries, including 82 files, expanding to **1,929,981,750 bytes**. Inspection found CPU implementations, CUDA 12/13 directories and Vulkan files; presence does not establish backend usability on this PC. Extraction passed the production validator. Windows Authenticode reported **Valid**, signed by **Ollama Inc.**, for `ollama.exe`.

The real executable then started through Moonzila's native Job Object helper with a dedicated loopback port, private model/home directories, cloud disabled and concurrency one. Windows listener/process ancestry matched the candidate executable, native helper and verifier process. `/api/version` returned 0.34.4 and `/api/tags` returned an empty model inventory. Cancellation reported owned process exit and the port could immediately be rebound. This checks startup, ownership and Stop; it does not measure model quality or inference speed.

The reproducible developer producer is `node --import tsx scripts/check-runtime-artifacts.ts`. It downloads about 1.46 GB if uncached, extracts about 1.93 GB temporarily, verifies the executable signature, checks owned startup and Stop, removes its temporary runtime, and saves file identities plus results in `.build/managed-artifact-check/verification.json`. It is opt-in and excluded from ordinary builds/tests. Production signing configuration, real lab/machine receipts, inference scheduling and the setup UI remain separate work.

The repeatable producer passed at 11:21 UTC on 27 September in **105.52 seconds**, using the already downloaded archive after rehashing it. The version endpoint became ready in **13.66 seconds**; this is executable startup time, not model loading or time to first token. Listener ancestry, isolated empty inventory, owned Stop, port release and temporary extraction removal all passed. The source suite passed **262 tests in 24 files**, including 54 artifact tests. An exact-value scan of 109 non-ignored repository files found neither of the supplied GitHub and Hugging Face credentials.
