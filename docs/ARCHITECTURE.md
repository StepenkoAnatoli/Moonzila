# MoonAliza architecture and current decisions

The full product architecture is defined in [reviewed decisions](specification/decisions.md) and the [implementation roadmap](superpowers/plans/2026-09-24-moonaliza.md). This document records current context recovery and offline Research Kit boundaries, not a replacement roadmap.

Electron main owns credentials, provider transport, native dialogs and the process broker. The utility-process engine owns durable SQLite state, project policy, operation approval, journaling and the agent loop. The renderer accesses only the validated preload bridge; its preflight guidance never grants tool or network authority. Errors cross the bridge only as `ErrorCodeSchema` codes (`src/shared/errors.ts`, public messages in `src/main/bridge.ts`); any other code surfaces as `INTERNAL_ERROR`. Tool policy refuses research tools with the contract code `RESEARCH_NOT_ALLOWED`. A refused profile endpoint is the public `INVALID_ENDPOINT`. A hard-linked file met by undo or recovery is the public `HARDLINK_REVIEW_REQUIRED`.

Context assembly is a pure engine operation before every model step. It reserves output capacity, evicts complete historical turns and compacts saved tool outputs into bounded references while retaining current call/result relationships. Originals remain in SQLite; retrieval is bound to the current session and passes live policy and cancellation checks. The UTF-8 estimate is a heuristic. Validated provider usage is a separate optional observation, never an invented exact preflight count. See [context recovery](specification/context-recovery.md) and its [primary evidence](../research/BRIEF.md).

Privacy changes require an explicit project-policy update. Profile edits bind to their revision; moving a credential-bearing profile to another endpoint or provider requires a new credential or explicit removal. Context recovery prepares a draft and never automatically repeats model calls, commands or edits. The context-recovery phase required no schema migration; folder-free chat below introduces schema v2 without new dependencies.

Provider streaming and later Research Kit integration must preserve these process boundaries. Research documents and imported artifacts are untrusted reference data, never instructions or permission grants. Genuine managed-model qualification, production trust inputs and signed delivery remain separate requirements.

The offline Research Kit stage adds opt-in guarded execution to the existing process broker. Before launching a child, the native helper opens read-only file guards and ancestor directory guards, rejects reparse points and hardlinked leaves, and waits for the owner to verify bytes and admit execution. Guards last until owned process cleanup. Failed or cancelled admission launches no child, admission has a deadline, and callers may stop the owned tree on output overflow. Ordinary command execution retains its existing behavior.

The [offline consumer](specification/research-kit-offline.md) uses independent strict boundary contracts, a reviewed inventory of 100 external runtime files and actual pinned producer/validator fixtures. It captures archive bytes once, checks bounded archive metadata and runs the pinned CLI with minimal environment and fixed arguments. Validity and research readiness stay separate from application permission. Successful imports retain content-addressed ZIPs outside project instruction discovery; each read verifies bytes against a process-local receipt bound to job/project revision and the complete dispatch identity. Restart requires fresh validation. Stage 2 since added the durable job lifecycle and the renderer surface, described below; renderer requests still never carry paths.

[Folder-free chat](specification/folder-free-chat.md) reuses the engine and conversation store with nullable session/run project identities. A general chat has a revisioned local/cloud policy and zero tool declarations. Main and engine intersect conversation and project policy and bind both revisions to each run. Every project tool entry rejects null scope. Stop, revocation and changed conversation policy invalidate active work.

Schema v2 preserves historical project sessions, runs, messages, FTS, journals and approvals through a transactional create/copy/drop/rename migration. A direct run-to-session FK and matching-scope triggers close the nullable composite-FK gap. Conversation scope is immutable: attaching or switching branches into a new session with only reviewed user text. Source policy restrictions survive branching. Navigation clears drafts; no tool output, approval or provider continuation is copied. Context recovery uses the same privacy-preserving branch with an unsent draft. Creating a session as part of Send never clears a draft until run admission succeeds. Native main-process dialogs are the only route to selecting/creating a workspace, followed by explicit trust. See the [design and migration sources](superpowers/specs/2026-10-01-folder-free-chat-design.md) and [implementation plan](superpowers/plans/2026-10-01-folder-free-chat.md).

Schema v3 makes research jobs run-less durable records: a constrained `research` projection plus an append-only `research_events` journal keyed by revision, with SQL triggers that refuse an unjournaled or stale change, identity rewrites, a second dispatch and `approved`. The engine (`src/engine/research.ts`) owns job state and admission; main drives collector facts through the `research.context/transition/recover` controls. Job notices use a separate `research` engine message, leaving `EventSchema` to runs. v2 research rows are kept verbatim in `research_legacy`. Earlier builds refuse a v3 database; migration is not a downgrade path. Schema v4 (Task 5, `migrateResearchReview`) rebuilds `research` and `research_events` in sqlite.org's documented order (create new tables, copy with explicit columns, drop, rename, recreate every index and trigger, then assert the object list and row counts before `user_version`), and refuses a v3 row in `reviewing` or `approved` with `MIGRATION_RESEARCH_STATE`. It adds the `packaging` status, the `engine` actor, nullable review columns (`review_session_id`, `review_run_id`, `review_digest`, `reviewed_package_sha256`, `reviewed_validator_revision`, `reviewed_bound_revision`) with checks per status, and replaces `research_readiness_reserved` with `research_readiness_digest`: `approved` only from `packaging`, with the frozen digest unchanged, a reviewed package unlike the collected one journaled on `collecting → collected`, and main's `KIT_APPROVED` journal row. `research_reviewed_immutable` freezes an approved row. The review edges live in `research-state.ts`; the store writes the review columns per edge, clearing them when a new review starts. `recoverInterrupted` keeps an `awaiting_review` run that a `reviewing` or `packaging` job names. The engine answers `research.review.context` (the review columns and the completed review writes since the latest `fresh` edge) and `research.recover` fills `freeze`, `packaging` and `reviewDiscard`; `reviewDiscard` never names a job in the owned list, whose workspace main's child may still use.

Collection is owned by main. `src/main/collector.ts` (`CollectorSupervisor`) drives each job from a re-read `research.context` through the pure planner `src/main/collector-plan.ts`, and only an `applied` reply lets it launch. A dispatcher that has started is never stopped, re-launched or re-dispatched; any outcome that could hide a remote run fails the job as `REMOTE_STATE_UNKNOWN`. A learned run id is spooled to `runs/<id>.json` before it is committed, so a lost commit is replayed at the next start. Each launch gets a 30-second vault grant: the token is decrypted only into the child's environment block and the grant is revoked once the launch is handed over. The token never reaches the engine, the database, notices or logs. `ResearchKit.prepareCollector` (`src/adapters/research-kit/adapter.ts`) shares `guardedRun` with the validator. The staged runtime and node are read-locked and rehashed, then the supervisor's admission check runs, and only then may the child start. A failed rehash is `INSTALLATION_INVALID`. Each launch has its own folder under `storage/collect`, and `close()` waits for running children. `src/main/index.ts` wires it in. At start it opens `<userData>/research-kit/collector.json`, builds the kit only from a valid `installation.json` and sweeps it. The collector reference is kept through the vault reconcile, and the supervisor is attached. Engine notices and `research.start/cancel` replies go to `observe`, and every engine child's `ready` goes to `engineReady`. `project.revokeTrust/policy.update` hold the project until the engine applies the change. Quit closes the supervisor, then the kit, then the engine. A downloaded package goes to the verified import, `src/main/research-import.ts` (`packageImporter`). It reads the GitHub run once, with the token from a 30-second grant in the request's `Authorization` header only, and no redirect followed. The run must be the one the job dispatched. Its commit and attempt, never the package's, go into the binding with the job's `collecting` revision and admitted policy revision. `ResearchKit.validate` then checks the package and retains its bytes. The supervisor commits the answer through `planStep`. `collecting → collected` requires the verification (digest, validator identity, bound revisions, the run's identity, run id and client ref, download digest unverified), journaled in that step's detail without a schema change. The engine refuses one that does not name the job's own revision, policy revision, run, client ref, repository and short ref. A package from another run fails `PACKAGE_IDENTITY_MISMATCH`, and a run that is not the dispatched one fails `RUN_IDENTITY_MISMATCH`. Anything not the package's fault parks the job as `import` until the next start; `validate` reports an unclassified failure outside the package's own content as `INSTALLATION_INVALID`, not `ARTIFACT_INVALID`. A collecting job's watch deadline is anchored on `dispatchedAt`, else on `createdAt`, so a damaged row is still watched and never past retention. A watch refused with `CREDENTIAL_DENIED` parks for credentials at once only when the saved token reference is gone; with the token still saved it is retried like any other refusal. The start input budget lives once, as `RESEARCH_INPUT_BUDGET` in `src/shared/params.ts`. The whole pre-start step (locks, rehash, admission) is bounded by `admissionMs` through `OwnedOptions.admissionTimeoutMs` in `spawnOwned`. A job held after a commit error stays in `ownedIds()` (and `busy()`) until the next app start, so an engine-only recovery never fails it. A watch counts its not-started refusals in a row, reset by any started watch or a park. The engine re-checks admission when it accepts a package (`collecting → collected`), as it does for the dispatch, inside the same transaction. Retained packages are written under `storage/work` and replaced by rename into the content-addressed store (not documented as crash-atomic on Windows); a torn file there is replaced, and a bad store entry defers as `INSTALLATION_INVALID`. Task 5's frozen review contracts live in `src/engine/review-contract.ts` (workspace, digest, reviewed package, failures, tool messages, review controls); `research.review.start` is main-owned. Admission compares the job's research level and trust revision, not the whole policy revision, so an inference-only policy edit keeps research running.

At each completed project step or phase, verify the work, push a branch and open a pull request. The user reviews and merges it. Do not merge on the user's behalf.

The September 30 reconciliation preserves upstream NDJSON/SSE transport, reused-index Ollama tool calls and native no-truncation flags. Accumulators retain validated optional terminal usage for the existing completion/event contract. Malformed usage does not invalidate an otherwise valid answer. Provider refusal inspection is limited to 64 KiB and its text never crosses into the engine. Incremental renderer output is deferred until the reviewed stream masker is implemented. The [Research Kit integration review](specification/research-kit-integration-review.md) is a future-stage design; it adds no runtime dependency or permission bypass.


Local repository access correction (0.8): directory tools accept only the explicit root aliases `.`, `./` and `.\` in addition to the existing empty root. Other path validation, trust, protected files and link checks are unchanged. URL-shaped inputs are rejected before filesystem inspection, without network access. Missing local paths, invalid paths, exclusions and unsupported URLs produce distinct public failures shared by the tool result and durable UI event; raw OS errors and absolute paths remain private. File/Git tool guidance makes the local workspace boundary explicit. The separate [public GitHub reader](specification/github-url-reading.md) implements URL reads through main-owned unauthenticated GET requests. Engine exposes read_github only for repositories in saved user text; main independently checks scope and live run/privacy/epoch before and after reads. Results bind to a run-pinned commit and source URL. General chat gains this remote read capability without any local tools. Cloning and GitHub credential storage are not implemented.

Research panel (plan Task 6, collection part): `src/renderer/ResearchPanel.tsx` opens per project from the details pane and talks only through `research.list/start/cancel` and `research.collector.read/save`, plus the preload's `onResearch` notices, which it filters by project and merges by revision so a late list reply never overwrites a newer notice. The start form groups the fields that become readable on the collector repository and names that repository; `acknowledgedPublic` comes only from an unticked checkbox, is held for the collector repository it was given for, and editing any public field or saving a different collector repository unticks it. The collector token input is uncontrolled: the token never enters React state or a DOM attribute, is cleared after a successful save, and the panel shows only `tokenConfigured`. `src/renderer/research-text.ts` holds one actionable message per job failure in the [collection spec](specification/research-collection.md), a test keeps the two in step, and research text is rendered as bounded plain text with direction controls removed. There is no review, authorize or approve control; evidence and brief reading show a placeholder until Tasks 4 and 5. A parked watch is not visible to the renderer (the job stays `collecting`), so the collecting state explains the possible waits instead. The import failures `RUN_IDENTITY_MISMATCH` and `PACKAGE_IDENTITY_MISMATCH` have their own messages. A collecting job's hint also says that a corpus waiting for verification resumes at the next start.

Renderer error ownership (0.8.1): navigation and explicit actions clear prior errors synchronously. The session-loading effect must not clear errors, because a newly created session can finish rendering after run admission has already refused a request. The refusal and retained draft remain visible; this changes no engine admission or recovery authority.

Desktop verification waits for durable terminal run status before checking the rendered GitHub answer. The fixture includes a valid six-second response to prevent reinstating a five-second end-to-end assumption. This test-only correction preserves production request deadlines and requires completed status, exact source identity and restart persistence.
